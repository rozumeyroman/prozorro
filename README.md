# Prozorro MCP

MCP-сервер для Claude, який знаходить і аналізує публічні закупівлі [Prozorro](https://prozorro.gov.ua). За замовчуванням він стежить за тендерами з **кібербезпеки** з очікуваною вартістю від **500 000 грн**. Інші теми (мережі, сервери) вмикаються перемиканням профілю фільтра.

Що вміє:

- підтягувати нові та змінені тендери з публічного API Prozorro і відбирати релевантні;
- шукати по локальній базі та показувати картку тендера: позиції, учасники, ціни за одиницю, переможці, договори;
- рахувати зведену аналітику: суми, розбивки, топ переможців і замовників, конкуренцію, знижки;
- вивантажувати результати в **Excel** (з аркушем «Аналітика»);
- завантажувати тендерну документацію (і пропозиції учасників) у теки «Замовник - Предмет - UA-ID»;
- перемикати й змінювати фільтри прямо в розмові з Claude.

Дані беруться з `public-api.prozorro.gov.ua` без авторизації. Релевантні тендери зберігаються в локальній базі SQLite.

## Встановлення

Потрібні Python 3.11+ і [uv](https://docs.astral.sh/uv/getting-started/installation/).

```bash
git clone https://github.com/rozumeyroman/prozorro.git
cd prozorro
uv sync
```

Клонуйте репозиторій у звичайну локальну теку, **не в синхронізовану хмарну** (Google Drive, iCloud, OneDrive). Хмарні клієнти блокують службові файли git, і `git clone` падає на `.git/config` lock. У хмару краще направити лише результати: Excel і документи (див. `PROZORRO_OUTPUT_DIR` у [Налаштуваннях](#налаштування)).

Перевірка без Claude:

```bash
uv run prozorro-mcp sync --since today   # підтягнути сьогоднішні тендери
uv run prozorro-mcp search               # що знайшлося
```

## Підключення до Claude Desktop

Відкрийте конфігурацію Claude Desktop (Settings → Developer → Edit Config):

- **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`
- **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`

Додайте сервер з **абсолютним** шляхом до теки проєкту:

```json
{
  "mcpServers": {
    "prozorro": {
      "command": "uv",
      "args": ["run", "--directory", "C:\\Users\\you\\prozorro", "prozorro-mcp"]
    }
  }
}
```

На macOS шлях має вигляд `/Users/you/prozorro`. Якщо Claude Desktop не знаходить `uv`, вкажіть повний шлях до нього: `where uv` на Windows або `which uv` на macOS. Змінні з розділу [Налаштування](#налаштування) передаються в полі `"env"`.

Перезапустіть Claude Desktop, і в списку інструментів з'явиться `prozorro`.

**Claude Code.** У репозиторії є `.mcp.json`, тож Claude Code, запущений у теці проєкту, сам запропонує підключити сервер. Підтвердьте це під час першого запуску.

## Як користуватися

Звичайний порядок роботи: **синхронізувати → шукати → вивантажити в Excel / завантажити документи**. Claude сам обирає потрібні інструменти, досить сформулювати запит:

| Задача | Приклад запиту |
|---|---|
| Нові тендери | «Підтягни нові тендери за сьогодні і покажи, що знайшлося» |
| Тендери, що приймають пропозиції | «Які тендери на SIEM чи EDR понад 1 млн грн зараз приймають пропозиції?» |
| Переможці | «Підтягни зміни за тиждень і покажи, хто й за скільки виграв» |
| Аналітика | «Зведення по кібербезпеці за III квартал: суми, топ переможців, частка торгів з одним учасником, медіанна знижка» |
| Щоденне оновлення | «Підтягни все нове з минулої синхронізації» |
| Деталі тендера | «Хто переміг у UA-2026-10-06-000123-a і з якою ціною за одиницю?» |
| Excel | «Вивантаж в Excel завершені тендери, де переможця визначили за останній тиждень» |
| Документи | «Завантаж документацію тендерів, що зараз приймають пропозиції» |
| Документи конкурента | «Завантаж документи UA-2026-09-01-011978-a разом із пропозиціями учасників» |
| Фільтри | «Перейди на фільтр it-infrastructure», «знизь поріг до 300 тисяч», «чому тендер UA-… не пройшов фільтр?» |

**Нові чи змінені тендери.** За замовчуванням `sync_tenders` бере тендери, **створені** за період. Щоб побачити свіжих переможців і договори в тендерах, оголошених раніше, просіть «з урахуванням змінених тендерів»: це параметр `only_new=false`.

**Період.** Вибірку можна задати за датою оголошення, за датою рішення про переможця чи договору або за **будь-якою з них** («оголошені АБО з рішенням за період»: `period_mode=either`). Верхня межа періоду (`until`, `created_to`, `period_to`) не включається.

## Інструменти MCP

| Інструмент | Що робить |
|---|---|
| `sync_tenders` | Підтягує з Prozorro тендери за період (`today`, `yesterday`, `3d`, `2026-10-01`, `last` — від попередньої синхронізації) з верхньою межею `until`. Зберігає ті, що пройшли фільтр; перервану синхронізацію продовжує (`resume`). Повертає статистику відсіювання за шарами |
| `search_tenders` | Пошук у локальній базі серед тендерів, що проходять активний фільтр: текст, тема, стадія, статус, вартість, дати оголошення й рішення, режим періоду, сортування, сторінки |
| `summarize_tenders` | Зведена аналітика по тій самій вибірці: кількість і суми, розбивка за статусом, темою й місяцем, топ переможців і замовників (за сумою й кількістю), середня кількість учасників, частка торгів з одним учасником, медіанна та середня знижка |
| `get_tender` | Картка тендера за id, номером `UA-…` або посиланням: позиції, лоти, учасники та їхні ціни за одиницю, переможці, договори, документи |
| `list_documents` | Документи тендера з посиланнями на файли |
| `export_excel` | Вивантаження в Excel, див. [Excel](#excel) |
| `download_documents` | Завантаження документації в теки на диску (один чи кілька тендерів або вибірка), див. [Тендерна документація](#тендерна-документація) |
| `calibrate_filter` | Звіт калібрування фільтра в Excel: що пройшло і чому, які відкинуті тендери схожі на тему |
| `prune_documents` | Прибирає теки документації тендерів, які не проходять поточний фільтр; спершу показує список, видаляє лише після підтвердження |
| `explain_filter` | Чому тендер пройшов чи не пройшов фільтр: збіги за кодами та ключовими словами, розрахунок вартості |
| `list_filters` / `use_filter` | Профілі фільтрів і вибір активного; вибір зберігається, доки його не змінити |
| `save_filter` / `delete_filter` | Власний профіль на основі наявного: поріг, коди, ключові слова, виключення |
| `status` | Активний фільтр, кількість тендерів у базі, остання синхронізація |

Інструменти `sync_tenders`, `search_tenders`, `summarize_tenders`, `get_tender`, `explain_filter`, `export_excel`, `download_documents` і `prune_documents` приймають параметр `filter`, щоб застосувати інший профіль лише до одного виклику.

## Фільтри

Тендери відбираються за **профілем фільтра** (`config/filters/*.yaml`). Профіль задає типи процедур, коди CPV, ключові слова, виключення та поріг вартості.

| Профіль | Що відбирає | Теми |
|---|---|---|
| `cybersecurity` (**за замовчуванням**) | Антивіруси/EDR/XDR, файрволи, проксі, SIEM/SOC, сканери вразливостей, DLP, захист пошти, DAST/SAST, BAS, PAM/IAM, Deception, аудит і пентест | `security_software`, `endpoint`, `network_security`, `siem_soc`, `identity`, `appsec_testing`, `data_email`, `deception`, `audit_testing`, `general`, `vendors` |
| `it-infrastructure` | Кібербезпека, мережеве та серверне обладнання | `cybersecurity`, `network`, `servers_storage`, `keyword` |

### Як працює відбір

1. **Стрічка змін, без завантаження тендера.** Відкидаються невідповідні типи процедур, спрощені закупівлі «звичайних» замовників (вони не можуть перевищити 200 тис. грн) і тендери з сумою лотів нижче порогу. Так відсікається понад половина стрічки.
2. **Тема.** Позиція тендера підходить:
   - за **основним кодом CPV** (однозначно за темою, наприклад `48730000-4` ПЗ безпеки);
   - або за **загальним кодом** (`48000000-8`, `72000000-5`, `30230000-0`…) разом із **ключовим словом** в описі: SIEM, EDR, FortiGate, «міжмережевий екран» тощо.
3. **Виключення.** Позиція відкидається, якщо:
   - її код у списку з 71 виключеного: ПК, монітори, пам'ять, диски, частини, кабелі, телефонія, прикладне ПЗ не за темою;
   - її опис **починається** з «кабель», «модуль пам'яті», «жорсткий диск», «блок живлення», «шафа» тощо, навіть під загальним кодом;
   - у позиції з загальним кодом є слова-виключення: офісна техніка, фізична охорона, відеоспостереження.
4. **Вартість.** Рахується сума лотів, у яких є позиції за темою, тож дорогий тендер на меблі з дешевим лотом на файрвол поріг не пройде.

Кожен тендер завантажується лише раз: рішення фільтра кешується, і подальші зміни нецікавих тендерів пропускаються. Детальніше: [`docs/tender-filter.md`](docs/tender-filter.md). Коди з поясненнями: [`docs/cpv-codes.md`](docs/cpv-codes.md).

### Керування фільтрами в розмові

- **Змінити активний фільтр** (діє, доки не змінити знову, і між сеансами): «Перейди на фільтр it-infrastructure».
- **Інший фільтр лише для одного запиту:** «Знайди тендери за фільтром it-infrastructure».
- **Змінити умови на льоту:** «Знизь поріг до 300 тисяч», «додай ключове слово Wazuh», «виключи код 79417000-0», «не бери позиції, що починаються з "трансивер"». Claude створює власний профіль на основі поточного (`save_filter`) і робить його активним.
- **Розібратися з конкретним тендером:** «Чому UA-… не потрапив у вибірку?» (`explain_filter`).

Вбудовані профілі не змінюються. Власні зберігаються в `~/Prozorro/Фільтри/` як YAML, тож їх можна редагувати й вручну.

### Калібрування

Щоб перевірити фільтр на реальних даних, побудуйте звіт калібрування за період, який уже синхронізовано:

```bash
uv run prozorro-mcp calibrate --created-from 2026-07-01 --created-to 2026-10-01
```

У Claude: «Зроби звіт калібрування фільтра за III квартал» (`calibrate_filter`). Звіт (Excel у теці `Експорт`) має три аркуші:

- **«Пройшли»:** усі позиції тендерів, що пройшли фільтр, з правилом, яке спрацювало (основний код, загальний код + ключове слово тощо). У колонці «Вердикт» позначте «ні» для тендерів не за темою.
- **«Відкинуті кандидати»:** відкинуті тендери, схожі на тему. У колонці «Мав пройти?» позначте «так» для пропусків.
- **«Як користуватися»:** статистика правил, тем, ключових слів і кодів.

Як шукаються пропуски. Синхронізація зберігає коротку довідку про кожен відкинутий тендер: назву, коди CPV, вартість і слова, схожі на кібербезпеку. Калібрування заново завантажує з API лише ризикові з них: відкинуті за вартістю, зі схожими словами або з кодами з `--cpv` (наприклад, `--cpv 48,72,3242`). Тендери, синхронізовані до появи довідок, дозбираються випадковими порціями по `--sample` за запуск (типово 300). Повторні запуски продовжують з того місця, де зупинилися, а аркуш «Як користуватися» показує, скільки ще залишилося. Щоб охопити весь квартал за один раз, задайте `--sample 200000` і `PROZORRO_CONCURRENCY=10`. Це займе 1–3 години, а перерваний запуск можна просто повторити.

За позначеним файлом уточнюються коди, ключові слова й виключення. Те саме пояснення для окремого тендера дає `explain_filter`.

Після зміни фільтра вже збережені тендери переоцінюються локально, без звернень до Prozorro. Тендери, які попередній фільтр відкинув, з'являться після наступного `sync_tenders`, бо рішення кешуються окремо для кожного профілю.

## Excel

`export_excel` створює файл у `~/Prozorro/Експорт/`. Кожен запит дає новий файл з датою й часом у назві, якщо не задати власну назву. До файлу потрапляють лише тендери, що проходять активний фільтр. Відбір можна звузити за стадією (тривають / завершені), статусом, темою, текстом, вартістю, датою оголошення, **датою визначення переможця чи підписання договору** або періодом з режимом «оголошені АБО з рішенням».

| Аркуш | Рядок | Основні колонки |
|---|---|---|
| **Аналітика** | — | підсумки (кількість, суми, учасники, частка з одним учасником, медіанна й середня знижка), розбивка за статусом, темою й місяцем, топ переможців і замовників за сумою та кількістю. Можна вимкнути (`include_summary=false`, у CLI `--no-summary`) |
| **Тендери** | тендер | номер з посиланням на prozorro.gov.ua, назва, замовник, ЄДРПОУ, регіон, тема, очікувана вартість і вартість релевантних лотів, статус, строк подання; переможець, сума, знижка, договір |
| **Позиції** | позиція | опис, CPV, кількість, одиниця, лот, чи відповідає темі та чому |
| **Переможці** | рішення | учасник, ЄДРПОУ, сума, дата рішення, очікувана вартість лота, знижка, кількість учасників, договір |
| **Пропозиції** | пропозиція учасника | учасник, ЄДРПОУ, сума, початкова сума, статус, переможець |
| **Ціни за одиницю** | позиція пропозиції | учасник, позиція, кількість, ціна за одиницю, переможець |

Суми й дати записані справжніми числами та датами Excel. Шапка закріплена, автофільтр увімкнено. Знижка рахується лише для порівнянних сум: в одній валюті й однаково з ПДВ або без.

Дані беруться з локальної бази, тож перед експортом переможців варто синхронізувати період зі зміненими тендерами (`only_new=false`).

## Тендерна документація

`download_documents` завантажує документи в `~/Prozorro/Документи/<Замовник> - <Предмет закупівлі> - <UA-ID>/`.

- **Що вибрати:** один чи кілька тендерів (номер, id або посилання; у CLI ще й файл зі списком `--ids-file`) або вибірку з бази з тими самими умовами, що й для Excel: ті, що тривають (`stage=active`), завершені (`stage=complete`), за періодом тощо. З вибірки береться до 20 тендерів за раз (`max_tenders`).
- **Пропозиції учасників:** з `include_bid_documents` завантажуються також публічні документи учасників (технічні та цінові пропозиції, листи авторизації) у підтеку `Пропозиції учасників/<учасник (ЄДРПОУ)>/`.
- **Актуальність:** перед завантаженням тендер оновлюється з API.
- **Повторний запуск** докачує лише нові, змінені або недокачані документи. Облік веде файл `_documents.json` у теці тендера, і він оновлюється **після кожного файлу**, тож обірваний запуск продовжується з місця зупинки. Файли пишуться спершу у `.part` і перейменовуються лише після завершення.
- **Прибирання:** після зміни фільтра теки тендерів, які більше не проходять фільтр, прибирає `prune_documents` (у CLI `docs --prune`, з `--yes` — видалення). Розглядаються лише теки, створені самим інструментом.
- **Що пропускається:**
  - підписи `.p7s` (їх можна ввімкнути через `include_signatures`);
  - конфіденційні документи: Prozorro не відкриває посилання на них.
- **Безпека й сумісність:** файли завантажуються лише з `*.prozorro.gov.ua`. Назви тек і файлів очищаються від символів, недопустимих у Windows, і від невидимих символів (пробіли нульової ширини тощо), які хмарні диски прибирають мовчки.

## Командний рядок

Ті самі можливості доступні з терміналу. Це зручно для довгих операцій, які не вкладаються в час очікування Claude Desktop.

```bash
# синхронізація
uv run prozorro-mcp sync --since 7d                    # тендери, створені за 7 днів
uv run prozorro-mcp sync --since 7d --all-modified     # + старші тендери, змінені за 7 днів (переможці, договори)
uv run prozorro-mcp sync --since 2026-07-01 --until 2026-10-01   # тендери, оголошені в III кварталі
uv run prozorro-mcp sync --since last --all-modified   # щоденне оновлення: усе з минулої синхронізації
uv run prozorro-mcp sync --resume                      # продовжити перервану синхронізацію

# пошук і аналітика
uv run prozorro-mcp search fortigate --stage active    # пошук у базі
uv run prozorro-mcp search --created-from 2026-07-01 --created-to 2026-10-01 --sort value_desc
uv run prozorro-mcp summary --period-from 2026-07-01 --period-to 2026-10-01 --period-mode either

# Excel
uv run prozorro-mcp export --stage complete --awarded-from 7d   # переможці за тиждень
uv run prozorro-mcp export --period-from 2026-07-01 --period-to 2026-10-01 --period-mode either -o ~/Q3.xlsx

# документи
uv run prozorro-mcp docs --stage active                # документація тендерів, що тривають
uv run prozorro-mcp docs UA-2026-09-01-011978-a UA-2026-09-16-009962-a --bids   # кілька тендерів з пропозиціями
uv run prozorro-mcp docs --ids-file список.txt         # тендери зі списку (по одному в рядку)
uv run prozorro-mcp docs --prune                       # які теки не проходять поточний фільтр
uv run prozorro-mcp docs --prune --yes                 # видалити їх

# фільтри
uv run prozorro-mcp filters                            # профілі фільтрів
uv run prozorro-mcp filters it-infrastructure          # зробити профіль активним
uv run prozorro-mcp calibrate --created-from 2026-07-01 --created-to 2026-10-01 --cpv 48,72   # звіт калібрування
```

Параметри вибірки однакові для `search`, `summary`, `export` і `docs`: `--query`, `--topic`, `--stage`, `--status` (можна кілька разів), `--min-value`, `--created-from`/`--created-to`, `--awarded-from`/`--awarded-to`, `--period-from`/`--period-to`/`--period-mode created|awarded|either`. Усі команди приймають `--filter <профіль>`, щоб застосувати інший фільтр лише до однієї команди.

Синхронізація зберігає результат і позицію в стрічці після кожної сторінки та виводить прогрес. Якщо процес обірвався, `sync --resume` продовжить з місця зупинки. Збільшити швидкість на довгих періодах допомагає `PROZORRO_CONCURRENCY` (наприклад, 8–12).

**Свої запити до бази.** Представлення `tender_profile_view` у `data/prozorro.db` містить рядок на кожну пару «тендер — профіль» разом із темами й вартістю релевантних лотів саме для цього профілю. Беріть значення звідти, а не з колонок таблиці `tenders`.

## Налаштування

| Змінна середовища | За замовчуванням | Призначення |
|---|---|---|
| `PROZORRO_OUTPUT_DIR` | `~/Prozorro` | Тека для Excel, документів і власних фільтрів; можна направити в хмарну теку, наприклад Google Drive |
| `PROZORRO_FILTER` | `cybersecurity` | Профіль за замовчуванням (поки не обрано інший через `use_filter`) |
| `PROZORRO_DB` | `data/prozorro.db` у теці проєкту | Файл бази SQLite |
| `PROZORRO_API_URL` | `https://public-api.prozorro.gov.ua/api/2.5` | API ЦБД (для тестів можна вказати sandbox) |
| `PROZORRO_CONCURRENCY` | `4` | Паралельні запити до API |
| `PROZORRO_TIMEOUT` / `PROZORRO_MAX_RETRIES` | `30` / `6` | Тайм-аут запиту в секундах і кількість повторів (на 429 та збої мережі) |
| `PROZORRO_FILTERS_DIR` | `config/filters` | Тека вбудованих профілів |
| `PROZORRO_FILTER_CONFIG` | — | Шлях до окремого YAML-профілю, який замінює профіль за замовчуванням |
| `PROZORRO_DOC_HOSTS` | `prozorro.gov.ua` | Хости, з яких дозволено завантажувати документи |

Приклад: результати в Google Drive на macOS (шлях залежить від вашого облікового запису):

```json
"env": { "PROZORRO_OUTPUT_DIR": "/Users/you/Library/CloudStorage/GoogleDrive-you@gmail.com/Мій диск/Prozorro" }
```

## Оновлення

```bash
cd prozorro
git pull
uv sync
```

Після цього перезапустіть Claude Desktop.

Після змін у правилах фільтра (нова версія профілю) перша синхронізація заново перевіряє тендери за період, бо кеш рішень прив'язаний до версії правил. Уже збережені тендери переоцінюються одразу, без мережі.

## Обмеження

- **Пошук за номером `UA-…`.** API Prozorro не шукає тендери за номером, тому номер працює лише для тендерів, які вже є в локальній базі. Для інших потрібен внутрішній id (32 символи) або синхронізація за потрібний період.
- **Тривалість операцій.** Синхронізація за кілька днів зі зміненими тендерами або завантаження документів для багатьох тендерів може тривати хвилини, довше, ніж Claude Desktop чекає на відповідь. Такі операції надійніше запускати з терміналу.
- **Довгі періоди.** Стрічка Prozorro впорядкована за часом останньої зміни, тож тендер, оголошений у липні й змінений учора, стоїть у ній на вчорашньому місці. Через це синхронізація за минулий період завжди проходить стрічку **до сьогодні**, а `until` лише відсікає тендери, оголошені пізніше. Квартал займає десятки хвилин. Для щоденної роботи використовуйте `--since last`.
- **Текст документів.** Читати вміст документів (наприклад, модель обладнання з технічної пропозиції переможця) сервер поки не вміє, лише завантажує файли.

План подальшої роботи: [`docs/development-plan.md`](docs/development-plan.md).

## Розробка

```bash
uv run --group dev pytest                # тести, зокрема наскрізний тест MCP через stdio
uv run --group dev ruff check src tests  # лінтер
uv run --group dev ruff format src tests # форматування
```

Тести не звертаються до мережі. Вони використовують імітацію API Prozorro (`tests/fake_prozorro.py`), побудовану на реальному прикладі тендера з документації Prozorro.

| Шлях | Вміст |
|---|---|
| `src/prozorro_mcp/server.py` | MCP-сервер та інструменти |
| `src/prozorro_mcp/sync.py`, `client.py` | синхронізація стрічки змін і клієнт API |
| `src/prozorro_mcp/filter.py`, `profiles.py` | фільтр і профілі |
| `src/prozorro_mcp/db.py`, `selection.py` | база SQLite і вибірки |
| `src/prozorro_mcp/export.py`, `documents.py` | Excel і завантаження документів |
| `config/filters/` | вбудовані профілі фільтрів |
| `docs/` | дослідження API, план розробки, опис фільтра, коди CPV |
| `api-specs/` | OpenAPI-специфікації API Prozorro |
